# Task Split

> Shared **criteria** (not a skill, not a procedure). Entry skills apply them; they own the steps.

## Statement

If the stated work will not fit **one understandable landing**, **split** it into sequential landings (each with one clear outcome) before writing—or get an **explicit human decision** to keep a larger bundle.

Prefer **one intent per landing**. File count and line count are secondary; **graspability of a single outcome** is the goal.

## Violations

Task shaping fails these criteria when any of the following holds:

| Criterion | Violation |
|-----------|-----------|
| Single outcome | The work cannot be restated as one outcome without "and also" unrelated intents |
| Sprawl | Intended surfaces (or discovery) clearly exceed what one short primary path can cover |
| Deferred split | Oversized scope was noticed, yet writing proceeded without a split or an explicit human OK to bundle |

## Not these criteria

- Drive-by hunks inside an already-scoped landing
- Hard gates (CI, propose/apply)
- Project management process beyond landing graspability
- How to narrate a change for humans
- Step-by-step write or submit workflows
